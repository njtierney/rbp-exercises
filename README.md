# R Best Practices Materials

This contains teaching materials used in **R Best Practices**.

It contains some deliberately badly organised R projects, for teaching. Every folder here shows a pattern that causes real trouble, and one folder shows where you'd rather end up. Nothing here is a judgement of anyone. These are all written by myself or tweaked and generated by an LLM.

## What's in here

- `01-everything-in-one-folder/` — scripts, data, figures, a Word document and
  a screenshot, all flat in one directory
- `02-no-clear-entry-point/` — eleven `.R` files and no way to tell which one
  runs first
- `03-outputs-mixed-with-inputs/` — raw data, cleaned data, a fitted model and
  figures, all sitting together
- `04-names-encode-history/` — `analysis_final_USE_THIS_ONE_v2.R`, and friends
- `05-tidy/` — the same analysis, organised. This is where we're heading
- `06-bad-style/` — code that runs. `messy-analysis.R` is laid out horribly,
  and `dodgy-logic.R` is laid out beautifully and is wrong
- `07-needs-review/` — code that runs, and that `{air}` and a linter will
  happily tidy without making it any easier to understand

## How it's used

**Chapter 1, project organisation.** The screenshots of these folders are the
worked examples of what goes wrong.

**Chapter 2, code style and readability.** `06-bad-style/` is the exercise
material. Run `{air}` over `messy-analysis.R`, and a linter over
`dodgy-logic.R`.

**Chapter 3, writing readable code.** `07-needs-review/analysis.R` is the
review exercise. Learners run the automated checks first, then discover that
the code is still hard to follow, and review it properly.

`08-real-code-from-the-wild/` is the optional second round.

Do not format `06-bad-style/`, `07-needs-review/` or
`08-real-code-from-the-wild/` when tidying this repo. Being awful is their job.

**Chapter 6, putting it all together.** Take one of folders `01` to `04` and
reorganise it towards `05-tidy/`.

Apply `{air}`. Apply a linter. Pull the repeated code into functions. Write a
README.

## A note on `05-tidy/`

It's small on purpose. Three scripts, one file of functions, a README.

The point isn't to have folders. It's to have a place where each kind of thing
goes, and to be consistent about it.
